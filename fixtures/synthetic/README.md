# Synthetic fixtures

**SYNTHETIC ONLY. No real operational data exists for PortTwin.**

## What is here

- `calibration-set.json` — 7 days of engine-generated observations (seeds 1000–1006 at `DEFAULT_PARAMS`). Calibrate on this set.
- `heldout-set.json` — 3 days of engine-generated observations (seeds 2000–2002, same parameters, independent draws). Evaluate on this set — the calibration never saw it.

Both files conform to the versioned validation-data schema (`schemaVersion: "1.0.0"`, see `src/sim/datasets.ts`) and are validated by the test suite.

## The gap these fixtures do NOT close

These fixtures were generated by the model itself from known parameters. They exercise the validation machinery end to end — schema parsing and version-gating, the calibration random search, the held-out evaluation workflow — and therefore prove **software correctness only**.

They say **nothing** about real-world accuracy. A low held-out loss here means "the workflow runs correctly", never "the model predicts the real port".

## What would close the gap

Measured operational data with `dataKind: "measured"`, from:

1. **The terminal operator** — TOS exports: hourly gate queue lengths, truck service times per stage, daily throughput (TEU and trucks), crane/berth utilization.
2. **ANP (port authority)** — vessel call schedules, gate transaction logs, any published operational statistics.

See `docs/ACCEPTANCE.md` for the full data ask and the acceptance criteria that depend on it.
